# Atlant transport measurements

These captures and benchmarks use generated data on isolated Linux network namespaces in WSL. They contain no live user sessions. `D` means download and `U` means upload. RTT is application echo round-trip time. Mbps counts verified application bytes, not all link traffic.

## Что изменилось в трафике после подключения

| Транспорт | Новые TCP-потоки за 25 с простоя, до → после | IP-байты за окно, до → после |
|---|---:|---:|
| TCP | 2–3 → 0 | 7 416–11 262 → 392 |
| XHTTP | 2–3 → 0 | 7 629–12 532 → 700–795 |
| QUIC | 2 → 0 | 7 510–7 722 → 541 |

Сравнение выше использует `before` (preview.11) и `after-chaffing` (промежуточная сборка preview.12) с одним сервером и одинаковой тестовой настройкой chaffing. Четыре параллельных потока, 20 Мбит/с на направление, RTT 50 мс, джиттер 2 мс и потери 1% на направление. `after-on-demand` показывает следующее изменение: UDP-ветка QUIC в смешанном режиме открывается при первом запросе. В финальном XHTTP-захвате `after-final` за каждую 25-секундную паузу видно шесть TCP-пакетов, ноль новых TCP-потоков и ноль UDP-пакетов. p50 RTT под нагрузкой — 56,4/56,1 мс, p95 — 73,3/60,9 мс (D/U). В `xhttp-130s` тестовый поток ответил после 130 секунд простоя в обоих прогонах. В захвате присутствует служебный обмен.

PCAP реконструированы по метаданным. Они содержат синтетические IP-заголовки и сокращённые TCP/UDP-заголовки. Сохранены относительное время, направление, исходная IP-длина, привязка к потоку и флаги TCP. Адреса заменены на TEST-NET, порты перенумерованы. MAC-адреса, абсолютные даты, содержимое пакетов, TCP sequence/ACK и значения опций, QUIC CID не экспортированы. Нулевые TCP sequence/ACK и усечённые записи ожидаемы. Захваты предназначены для анализа, а не для воспроизведения сети. Файлы `*-phases.json` задают относительные границы. В `resume` учитывается открытие тестовых потоков нагрузки. Кадры выше MTU могут быть результатом агрегации на виртуальном интерфейсе, их размеры нельзя переносить на физический канал.

## Скорость

Локальная RAM-цель, четыре параллельных потока и отдельный echo-поток. На канале 2,5 Гбит/с без заданной задержки и потерь каждое направление измерялось шесть секунд.

| Транспорт | Повторная база, Мбит/с D / U | Итоговый кандидат, Мбит/с D / U | p95 итогового кандидата, мс D / U |
|---|---:|---:|---:|
| TCP | 1083 / 1207 | 1607 / 1554 | 13,1 / 10,5 |
| XHTTP | 1276 / 1195 | 1341 / 1276 | 12,3 / 9,9 |
| QUIC | 1141 / 929 | 1130 / 1106 | 6,9 / 5,0 |

Первый прогон базы дал 1539/1513 для TCP, 1319/1170 для XHTTP и 1086/1071 для QUIC. XHTTP показал небольшой прирост относительно обоих прогонов базы. TCP и QUIC дали заметный разброс. Большие порции передачи ухудшили часть результатов и были отменены. На стенде 500 Мбит/с база уже давала 462–477 Мбит/с. Итоговый кандидат скорости и клиент в финальном PCAP — разные сборки. Сравнение наблюдаемого трафика не измеряет точность DPI или ML-классификатора.
